WebSocket

The event stream: a device keeps the connection open, and the server pushes signals into it the moment they’re sent.

Connecting

WS/v1/streamdevice
wss://api.lovearound.me/v1/stream
Authorization: Bearer dev_…

The token goes in a header, as with REST. The browser’s built-in WebSocket can’t set headers, so connect from your own program: on a board, in Node, Python, on a phone.

A web page signed in to the account (like the web app) can use a ticket instead: POST /v1/stream/ticket with the app token, then open wss://api.lovearound.me/v1/stream?ticket=… without a header. A ticket works once, within 30 seconds; get a new one for every connection.

Parameters

Parameter
anyone=trueReceive “someone out there” signals from strangers. Off by default for devices, on for the apps. Each connection decides for itself, unless the device’s accept_anyone was set in an app: that wins
anyone=falseDon’t receive them
ticket=…A one-time ticket in place of the Authorization header, for a browser

Responses

CodeWhat to do
101The connection is open; ready comes next
401The token is wrong, the device was disconnected, or the ticket was already used or ran out. Reconnecting with the same token won’t help
503The server is updating or couldn’t read the device’s settings. Connect again in a couple of seconds

From the server

Each message is a text frame with one JSON object. The type field says what kind of message it is. Besides them the server sends two WebSocket control frames, ping and close.

ready

{ "type": "ready" }

The first message after connecting: from now on, signals are delivered. Things may have changed while you were disconnected, so on every ready reload whatever you keep locally, such as the contact list.

event

{
  "type": "event",
  "event": {
    "id": "ev_q8ZkT1mW4aLp0sXv7cRb",
    "type": "signal",
    "v": 1,
    "at": "2026-10-10T14:00:00.000Z"
  }
}
Field
event.idThe event’s identifier. One event reaches all of the recipient’s devices with the same id
event.typeOnly signal for now
event.vThe format version of this type. For signal it’s 1
event.atWhen the server accepted the event

Someone sent you a heart — time to glow. The event has no sender. A signal from a close one and a signal to “anyone” look exactly the same.

sync

{ "type": "sync", "what": "contacts" }

The contact list changed: someone was added, renamed, recolored, moved or removed, or another account was merged into this one. If your device shows the list, reload it with GET /v1/contacts. If it doesn’t, you can skip this message.

Only apps and devices with the send permission get it: one without has no list to read. The apps also get { "type": "sync", "what": "devices" } when a device’s settings, battery or what it’s made of change.

settings

{ "type": "settings", "rev": "r3f9a0c1d2e", "name": "Ring in the hall", "values": { … }, … }

A device’s settings, always the whole thing: after ready and after every change. Only for a device that has told the server what it is made of. Apply them, keep them, and report the rev over REST. The fields are in Device protocol.

preview

{ "type": "preview" }

The owner tapped Try it on the device’s card: show one heart as the device is set now. It is not a signal, and nobody sent it but the owner. See Device protocol.

ping frame

Every 25 seconds. WebSocket libraries answer it with pong on their own.

close frame

The server closes the stream itself, with no code or reason, when:

  • the device was disconnected in the app;
  • the device’s settings changed (what it does, quiet hours, “someone out there”): it reconnects with the new ones. A change of its light, sound or button doesn’t close the stream: a settings message comes instead;
  • the device got a new token: the old one then gets 401;
  • the account was deleted, or merged into another (the devices move there and reconnect);
  • the server is updating: everyone moves to the new version.

Reconnect with the usual pause. If the device was disconnected or the account deleted, the next attempt gets 401.

Skip what you don’t know. If you don’t recognise the type, event.type, event.v or what, do nothing. The server will add new messages, and older devices should quietly ignore them.

From the client

The stream is one-way: there are no messages for the client to send. Send signals with POST /v1/events: sending has one path, and every check and limit lives in one place.

pong frame

The answer to the server’s ping. Your library sends it for you.

ping frame

Send your own every 30 seconds, and the server answers with pong. No pong within a few seconds means the connection is dead, even if the socket doesn’t know it yet: close it and reconnect.

Anything else

Text and binary messages are ignored. A close frame closes the stream.

Keeping the connection alive

  • Ping. Answer the server’s ping and send your own every 30 seconds.
  • Reconnecting. Connections drop: Wi‑Fi goes away, the server updates. Reconnect with a pause: start at one second and double it up to a minute; after ready, reset it to one second.
  • When not to reconnect. If connecting returns 401, the token is wrong or the device was disconnected: forget the token and tell the owner instead of hammering the server.
  • receive off is not an error. A device whose receive is switched off connects as usual and gets its settings and sync, but no signals. It starts getting them again once receive is back on: the server drops the stream, and the device reconnects with the new rights.

Several connections

One account can have any number of open streams: a Mac, Windows, Linux, the web app, a toy, a lamp. Every event reaches each of them. One device can also hold several connections, but one is usually enough.

Only streams with anyone=true get “anyone” signals, along with Telegram chats that take them. Such a signal goes to one person, and one person gets at most one an hour.

Examples

From a terminal

With websocat:

websocat -H "Authorization: Bearer dev_…" \
  wss://api.lovearound.me/v1/stream

Node.js

With the ws package (npm i ws). Save it as stream.mjs and run LOVEAROUND_TOKEN=dev_… node stream.mjs:

import WebSocket from "ws";

const URL = "wss://api.lovearound.me/v1/stream";
const TOKEN = process.env.LOVEAROUND_TOKEN; // dev_…
let delay = 1000;

function connect() {
  const ws = new WebSocket(URL, { headers: { Authorization: `Bearer ${TOKEN}` } });
  let ping;

  ws.on("open", () => {
    // ping every 30 s; no pong by the next one means the connection is dead
    let alive = true;
    ws.on("pong", () => { alive = true; });
    ping = setInterval(() => {
      if (!alive) return ws.terminate();
      alive = false;
      ws.ping();
    }, 30_000);
  });

  ws.on("message", (data) => {
    let msg;
    try { msg = JSON.parse(data); } catch { return; }
    if (msg.type === "ready") { delay = 1000; console.log("online"); }
    if (msg.type === "event" && msg.event?.type === "signal" && msg.event?.v === 1) {
      console.log("💗 someone thought of you");
    }
    // skip everything else
  });

  ws.on("error", (err) => {
    if (/Unexpected server response: 401/.test(err.message)) {
      console.error("the token doesn't work: the device was disconnected");
      process.exit(1);
    }
    // an error is always followed by close
  });

  ws.on("close", () => {
    clearInterval(ping);
    setTimeout(connect, delay);
    delay = Math.min(delay * 2, 60_000);
  });
}

connect();

Python

With the websockets package, version 14 or later (pip install websockets):

import asyncio, json, os
import websockets
from websockets.exceptions import InvalidStatus

URL = "wss://api.lovearound.me/v1/stream"
TOKEN = os.environ["LOVEAROUND_TOKEN"]  # dev_…

async def main():
    delay = 1
    while True:
        try:
            async with websockets.connect(
                URL,
                additional_headers={"Authorization": f"Bearer {TOKEN}"},
                ping_interval=30,
            ) as ws:
                async for raw in ws:
                    msg = json.loads(raw)
                    if msg.get("type") == "ready":
                        delay = 1
                        print("online")
                    ev = msg.get("event") or {}
                    if msg.get("type") == "event" and ev.get("type") == "signal" and ev.get("v") == 1:
                        print("💗 someone thought of you")
        except InvalidStatus as e:
            if e.response.status_code == 401:
                raise SystemExit("the token doesn't work: the device was disconnected")
        except (OSError, websockets.WebSocketException):
            pass  # dropped, 503, no network: just reconnect
        await asyncio.sleep(delay)
        delay = min(delay * 2, 60)

asyncio.run(main())
