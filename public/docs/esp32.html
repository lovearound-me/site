Your own device

ESP32 toy

A soft toy with a ring of LEDs in its tummy and a button in its paw. It glows when someone thinks of you, and pressing the paw sends a heart to someone close.

Receive

The toy keeps a WebSocket open, and the server tells it about every heart.

Send

The button makes one HTTP request and sends a heart to a person in your list.

Overview REST API WebSocket ESP32 toy

A device only sees your contact list and can only send and receive signals. It can’t change the list, delete the account or find out who sent a signal: nobody knows that.

1Get a device token

Click the heart in the menu bar (on Windows, in the tray next to the clock) → Settings → Devices (Настройки → Устройства). Give the device a name, for example “Kitty on the shelf”, tick what it can do — receive, send or both — and click Connect device (Подключить устройство).

The app shows the token once:

dev_4kq9XbT2mWc7RfLp8sHn3vYzAe6uJd5G

Copy it and keep it to yourself: anyone with it can send hearts in your name. If the token leaks or the device gets lost, disconnect the device in the same place and the token stops working at once.

The app speaks only Russian for now, so the menu names are given in both languages.

2Find out whom to send to

The easiest way is the menu: right-click a person → Copy id for a device (Скопировать id для устройства). Or ask the server for the list:

GET /v1/contacts
{
  "contacts": [
    { "id": "DXEjjB91rJYQvgaGGdsx", "label": "Mom", "position": 0, "close": true, … },
    { "id": "Qm3LkT0pZ8aW2vRcN5yE", "label": "Anna", "position": 1, "close": false, … }
  ]
}

More about the fields in REST API. id is the person’s identifier in your list. Map the buttons on your device to the ids you want, for example “left paw — Mom”.

3What you’ll need

  • A board. Any ESP32, for example an ESP32‑DevKitC or an ESP32‑C3 Super Mini. The ESP32 only sees 2.4 GHz Wi‑Fi networks, and the network name is case-sensitive: “GGWP” and “ggwp” are different networks.
  • LEDs. A WS2812B ring of 12–16: data in on GPIO 5, power on 5V and GND.
  • A button between GPIO 4 and GND; the pull-up is enabled on the board.
  • A body. A soft toy: the LEDs in its tummy, the button in its paw.

Libraries for the Arduino IDE, from the Library Manager: WebSockets (Markus Sattler), ArduinoJson version 7 (Benoit Blanchon; the sketch won’t build with version 6), Adafruit NeoPixel.

4The sketch

Fill in your Wi‑Fi, token and contact id at the top and upload it to the board.

#include <WiFi.h>
#include <HTTPClient.h>
#include <WiFiClientSecure.h>
#include <WebSocketsClient.h>
#include <ArduinoJson.h>
#include <Adafruit_NeoPixel.h>

// ---- your settings ----------------------------------------------------
const char* WIFI_SSID  = "my-network";
const char* WIFI_PASS  = "password";
const char* TOKEN      = "dev_…";                  // from Settings → Devices
const char* CONTACT_ID = "…";                      // whom the button sends to
const uint32_t COLOR   = 0xE86A9A;                 // glow color

const char* HOST = "api.lovearound.me";
const int LED_PIN = 5, LED_COUNT = 12, BUTTON_PIN = 4;
// -----------------------------------------------------------------------

Adafruit_NeoPixel ring(LED_COUNT, LED_PIN, NEO_GRB + NEO_KHZ800);
WebSocketsClient ws;

void fill(int level) {
  const uint8_t r = COLOR >> 16, g = COLOR >> 8, b = COLOR;
  ring.fill(ring.Color(r * level / 255, g * level / 255, b * level / 255));
  ring.show();
}

// Three soft flashes, like on the Mac.
void glow() {
  for (int flash = 0; flash < 3; flash++) {
    for (int i = 0; i <= 255; i += 5) { fill(i); delay(5); }
    for (int i = 255; i >= 40; i -= 5) { fill(i); delay(5); }
  }
  ring.clear(); ring.show();
}

void onMessage(WStype_t type, uint8_t* payload, size_t length) {
  if (type != WStype_TEXT) return;
  JsonDocument msg;
  if (deserializeJson(msg, payload, length)) return;
  // Skip unknown types and versions.
  if (msg["type"] == "event" && msg["event"]["type"] == "signal" && msg["event"]["v"] == 1) {
    glow();
  }
}

void sendSignal() {
  WiFiClientSecure tls;
  tls.setInsecure();  // fine for a prototype; in a finished device set the root certificate with setCACert
  HTTPClient http;
  http.begin(tls, String("https://") + HOST + "/v1/events");
  http.addHeader("Authorization", String("Bearer ") + TOKEN);
  http.addHeader("Content-Type", "application/json");
  int code = http.POST(String("{\"type\":\"signal\",\"to\":{\"contact\":\"") + CONTACT_ID + "\"}}");
  http.end();
  // A short white flash: it's on its way.
  if (code == 202) { ring.fill(ring.Color(40, 40, 40)); ring.show(); delay(150); ring.clear(); ring.show(); }
}

void setup() {
  pinMode(BUTTON_PIN, INPUT_PULLUP);
  ring.begin(); ring.setBrightness(120); ring.clear(); ring.show();

  WiFi.begin(WIFI_SSID, WIFI_PASS);
  while (WiFi.status() != WL_CONNECTED) delay(300);

  ws.beginSSL(HOST, 443, "/v1/stream");
  ws.setExtraHeaders((String("Authorization: Bearer ") + TOKEN).c_str());
  ws.onEvent(onMessage);
  ws.setReconnectInterval(5000);      // reconnect after a drop
  ws.enableHeartbeat(30000, 5000, 2); // ping every 30 s
}

void loop() {
  ws.loop();
  static bool wasDown = false;
  bool down = digitalRead(BUTTON_PIN) == LOW;
  if (down && !wasDown) sendSignal();
  wasDown = down;
  delay(10);
}

Upload the sketch, and the toy will glow when someone thinks of you. Pressing the paw sends a heart to Mom.

The sketch takes up almost all of the default program memory. If you extend it, choose Tools → Partition Scheme → Huge APP in the Arduino IDE.

What the sketch does: the toy opens the /v1/stream stream, glows on every signal event and skips anything it doesn’t know. The button sends POST /v1/events. The library handles drops on its own: it reconnects after 5 seconds and pings every 30 seconds. All messages and status codes are described in WebSocket and REST API.

For the toy to also get “someone out there” hearts from strangers, connect to /v1/stream?anyone=true. Such a signal arrives at most once an hour.

Where to take it

  • Several buttons. Each with its own contact and color: the mapping lives on the device; the server knows nothing about colors.
  • A vibration motor or a buzzer instead of LEDs.
  • Quiet at night. The ESP32 can get the time over NTP and stay dark from 23:00 to 8:00.
  • Wi‑Fi and token without reflashing. Through a setup access point, for example with the WiFiManager library.
  • A screen and choosing a person. A board with a screen, for example the LilyGO T‑Display‑S3 AMOLED: two buttons scroll the list, after 3 seconds the heart flies to the chosen person, and the last item is “Someone out there”. The list comes from GET /v1/contacts and refreshes on {"type":"sync"}.

Security

  • The token lets anyone send hearts in your name. Don’t publish a sketch with a real token in it.
  • A disconnected device loses access at once, open connection included.
  • Don’t leave setInsecure() in a finished device. Check the server’s certificate with setCACert.
