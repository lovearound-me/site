REST API

Anything that changes state or sends a signal is a plain HTTP request with JSON.

Overview REST API WebSocket ESP32 toy

Basics

https://api.lovearound.me
  • Authorization: Authorization: Bearer <token> on every request. The kinds of token are in the overview.
  • Request body: JSON with the Content-Type: application/json header.
  • Time: ISO 8601 strings in UTC, for example 2026-10-10T14:00:00.000Z.
  • X-Client (optional): the client’s name and version, for example my-lamp/1.2. It goes into the server log along with the signal and helps track down problems. Without it, the log gets the User-Agent.

Each request is marked with who may call it:

app — the app token only; a device gets 403. device — a device token works too.

Errors

An error comes with an HTTP status and a body:

{ "error": "already in contacts" }

The text in error is for people and logs. Decide by the status code, not the text.

CodeWhen
400The request makes sense but a value is wrong: an empty label, a malformed code, nothing to change. Also 400 when the body isn’t JSON
401No token, or it’s wrong or expired, the device was disconnected, the account was deleted
403A device token can’t do this: the request is app-only, or the device lacks the permission
404No such contact or device in your account
409The person is already in the list, or there are already 20 devices
415No Content-Type: application/json
422The JSON doesn’t fit the schema: a required field is missing, an extra field in an event, a wrong type. The response body here is plain text, not JSON
429A limit was hit, see below
5xxSomething failed on the server. Retry later, with a pause

Signals

POST/v1/eventsdevice, send permission

Send a signal to a person in your list:

{ "type": "signal", "to": { "contact": "DXEjjB91rJYQvgaGGdsx" } }

Or to a random person online who accepts signals from anyone (never to yourself):

{ "type": "signal", "to": { "anyone": true } }
FieldType
typestringOnly "signal" for now. Anything else is 400
to.contactstringA contact’s id from GET /v1/contacts
to.anyonebooltrue — someone out there. Not allowed together with contact

A signal has no data field: with one, you get 400. There must be no other fields either, or you get 422.

The response is 202 Accepted:

{ "id": "ev_q8ZkT1mW4aLp0sXv7cRb" }

202 means “accepted”. The response doesn’t say whether the recipient was online or how many devices they have. A signal to a contact added with a wrong Love ID is accepted too and goes nowhere. “Anyone” also returns 202, even when nobody is online.

Errors: 400 a wrong type or to, 403 the device may not send, 404 no such contact, 429 “anyone” was already used this hour (every attempt counts).

Contacts

The contact object:

{
  "id": "DXEjjB91rJYQvgaGGdsx",
  "label": "Mom",
  "position": 0,
  "close": true,
  "created_at": "2026-10-02T09:12:44.120Z"
}
FieldType
idstringThe person’s identifier in your list. Other lists know nothing about it
labelstringYour label, 1–64 characters. The person never sees it
positionintOrder in the list
closeboolA close one: a circle at the top of the app’s menu. Handy to show first
created_atstringWhen they were added
GET/v1/contactsdevice

The whole list, by position, then by when they were added.

{ "contacts": [ { "id": "DXEjjB91rJYQvgaGGdsx", "label": "Mom", … }, … ] }

When the list changes, a sync arrives over WebSocket: load it again then.

POST/v1/contactsapp

Add a person by their Love ID:

{ "code": "GSSV7-A33HN", "label": "Mom", "close": true }

code is 10 characters from 23456789ABCDEFGHJKMNPQRSTVWXYZ; case and dashes don’t matter. close is optional and defaults to false. A new contact goes to the end of the list.

The response is 201 with the contact object. A wrong but well-formed code also gets 201: the server doesn’t say whether anyone is behind a code.

Errors: 400 a malformed code, an empty label or one longer than 64 characters, your own code, 200 people already in the list. 409 this person is already in the list. 429 too many additions this hour.

PATCH/v1/contacts/{id}app

Change the label, the position or the “close” mark. Any subset of the fields:

{ "label": "Mommy", "position": 2, "close": false }

The response is 200 with the updated contact. To reorder several people, send one request for each. Errors: 400 an empty body or a bad label, 404 no such contact.

DELETE/v1/contacts/{id}app

Remove from the list. The response is 204, also when the contact is already gone. The person isn’t told.

Devices

The device object:

{
  "id": "r7Hc2LqW9xPz4KmN0aTe",
  "kind": "toy",
  "name": "Kitty on the shelf",
  "capabilities": ["receive", "send"],
  "created_at": "2026-10-20T18:03:10.442Z",
  "last_seen_at": "2026-11-01T07:55:02.918Z"
}
FieldType
kindstringtoy or custom
namestring1–64 characters
capabilitiesstring[]receive — receive signals, send — send them
last_seen_atstringWhen the device last opened a stream. Missing if it never has
GET/v1/devicesapp

The devices, by creation time: { "devices": [ … ] }.

POST/v1/devicesapp
{ "name": "Kitty on the shelf", "kind": "toy", "capabilities": ["receive"] }

kind defaults to custom, capabilities to both. The response is 201:

{ "device": { "id": "r7Hc2LqW9xPz4KmN0aTe", … }, "token": "dev_4kq9XbT2mWc7RfLp8sHn3vYzAe6uJd5G" }

The token is shown only here; the server keeps just its hash. Errors: 400 a bad name, kind or capabilities, 409 there are already 20 devices.

DELETE/v1/devices/{id}app

Disconnect a device. Its token stops working at once and the streams it opened are closed. The response is 204, or 404 if there is no such device.

Account

GET/v1/meapp

Your own account. On the first call after sign-in, the server creates it and issues a Love ID.

{
  "uid": "…",
  "created_at": "2026-09-28T11:40:00.000Z",
  "invite_url": "https://lovearound.me/i/GSSV7-A33HN"
}

uid is your own identifier. The server never hands out anyone else’s.

DELETE/v1/meapp

Delete the account with all its data: the list, devices and their tokens, the Love ID, the sign-in. Open streams are closed. The response is 204. This can’t be undone.

Stream

WS/v1/streamdevice, receive permission

Receiving signals. Described in WebSocket.

POST/v1/stream/ticketapp

A one-time ticket for opening the stream from a browser, which can’t put the token in a header there. No body.

{
  "ticket": "k3VqT9…",
  "expires_in": 30
}

Open /v1/stream?ticket=… within expires_in seconds. A ticket works once and only for the stream.

Health check

GET/no token

Answers 200 with the text needed.

Try it from a terminal

TOKEN=dev_…
API=https://api.lovearound.me

curl -H "Authorization: Bearer $TOKEN" $API/v1/contacts

curl -X POST $API/v1/events \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"type":"signal","to":{"contact":"DXEjjB91rJYQvgaGGdsx"}}'
